# 画笔白框、结束提示与微信上下文修复

## 改动

- 画笔落笔态从通用 `drawing` 改为 `is-drawing`，避免继承绘画应用的白底画布样式。按钮禁止长按文本选择及图片拖动命中。
- 姿态位置或落笔命令被拒绝后，停止该轮原生订阅及待发位置；旧回执不能终止新手势。同一手势的失败只提示一次，重复回执不提示，抬手与丢失捕获不重复结束笔画。
- 微信返回直接到桌面，进入直接选择陈总。保留聊天、草稿和手机待机桌面的激活规则。
- 点击输入框时，从实际可见消息中选择已选中的有效消息或最后一条有动作的来信，跳过结尾闲聊。滚动后重新点击输入框可读取新的可见来源。动作表单继续按会话、消息、动作分别保存。
- 陈总沿用销售故事；老婆、Alex 沿用导入的 Hover 意图映射及限制条件。原导入映射没有家庭群案例，家庭群新增原文备忘适配，复用 Hover 备忘 Sheet，不推测日期、地点或真实操作。闲聊不生成虚构业务动作。

## 验证

- 类型检查、36 项核心测试、生产构建通过。
- 浏览器 7 个场景通过（整套 6 项，修正新测试的桌面选择器后重跑剩余 1 项）。覆盖所有会话、当前消息来源、草稿保留、返回重进、读屏时序、WPS、字幕适配、FC 与 Mario。
- 画笔按住时验证光标高度 28 px、背景透明；截图在 `artifacts/visual-qa/pen-held-no-white-box.png`。
- 注入“指向已结束”失败并重复投递回执，验证只发送一个被拒绝的位置命令，提示消失后不再出现，原生传感器适配停止。该故障注入属于浏览器测试。
- 两个签名 HAP 构建、覆盖安装成功。真机通过原生 TCP 重新配对；WPS 第 1 页编辑状态、手机开始放映和画笔指针可见。真机截图在 `artifacts/pen-wechat-fixes/tablet-held.png`。
- 真机确认微信直接显示陈总，手机保持待机；点击输入入口后显示日程、导航、飞书三个动作。切换家庭群后读到屏幕上的花盆消息及备忘入口；返回桌面并重进微信仍直接显示陈总。
