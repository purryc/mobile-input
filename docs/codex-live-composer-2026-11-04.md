# Codex 执行中输入与实时操作 · 2026-11-04

## 问题与实际证据

执行中的 Codex 空输入框只暴露 Stop；写入专用虚构草稿后，AX 暴露的实际按钮为 **Queue**，enabled=true。此前 submitButton 只识别 Send 类标签，因此手机虽能输入却无法发送。真实未发送草稿探测已通过写入、读回 Queue、恢复空白，全程没有调用 Send / Queue / Steer。

隐私证据在忽略目录 `artifacts/codex-live-actions/`。后续手机联动核对时出现前台切换和非空草稿，保护规则在写入前中止；没有覆盖该草稿。首次测试草稿已确认恢复。

## 实现

- Mac 适配器读取当前 Composer 范围内唯一、可用的 Send / Queue 控件，提供真实标签、操作身份和类型。执行中不额外禁止输入或目标支持的发送。Codex 使用已经验证的聚焦控件＋Space 激活路径，避免其按钮不支持 AXPress 的问题。
- 手机共享 Agent Composer 直接显示该操作标签。只在用户明确点击后携带当前动作身份提交，仍须文本、材料、归属校验；未确认结果不自动重发。
- 独立读取 Composer 附近精确命名的 Steer / Steer now 按钮，显示独立操作。提交 Queue 不自动 Steer；重连不重放。按钮绑定当前会话、编辑器、AX 控件和排队文本指纹，失效或被替换时拒绝旧请求。
- Steer 点击期间防止重复操作，未知结果锁住该动作并要求核对。回读只验证对应界面动作被接受，不宣称模型已经完成。
- 发送回读新增应用、窗口和编辑目标检查；切目标后不能把别的会话结果当作当前发送成功。
- 保留 Recents 原顺序、实际执行状态、未知状态隐藏、共用 InputDock、附件流程和 USB 优先。
