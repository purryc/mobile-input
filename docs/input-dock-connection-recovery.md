# 输入工具误禁用与断线恢复

## 本轮观察

用户反馈数字、emoji 无法输入，语音及编辑工具变灰。真机 UI 树确认手机处于“连接已断开”，编辑工具与语音 `enabled=false`；平板 Wi-Fi 地址为 `100.66.131.229`，手机 wlan0 没有 IPv4 地址，连接表单仍使用旧热点地址 `172.20.10.4`。不能据此把按钮禁用归因于数字／emoji 键码。

## 修正

- 已激活的 WorkBuddy 输入页在断线后保留，避免换成通用输入页并丢掉原任务编辑状态。
- 数字、表情、字母及剪贴板属于本地编辑，断线／草稿保护时继续可用。写入仍暂停，内容按原任务持久化。
- 草稿区显示实际原因与“重新连接／恢复到当前目标”。断线语音入口打开连接面板；受保护目标提示先恢复，恢复本身不启动录音、不提交任务。
- 远程鼠标、任务提交和依赖目标的语音保持连接与目标约束；离线按键不发远程命令。重连后明确恢复才同步未确认内容。
- 意图解析在断线或保护状态暂停；不会因为离线编辑而生成失败提示。

## 验证

浏览器、构建、真机结果分开记录；证据在 `artifacts/input-dock-recovery/`。用户需将两端接入同一热点，才可继续真实端到端验证。

已通过 TypeScript、95 项核心／协议测试、5 项相关浏览器测试。专项实际断开浏览器连接，验证原 WorkBuddy 组件保留、离线数字／emoji 输入与恢复确认、语音按钮打开连接入口，重连前后不自动提交任务。Web 与签名 HAP 结果以本轮构建日志为准。

连接入口补充：平板打开连接面板时向原生端重新查询当前地址，已有 TCP 服务不重启；避免换网后二维码一直携带启动时旧 IP。

两端签名包已覆盖安装并启动。平板真机打开连接面板读回当前 `100.66.131.229`，旧热点地址已刷新。手机当时仍无 Wi-Fi IPv4，已请求用户连同一热点；本轮真机数字／emoji 同步、真实语音和拔线验证仍待网络恢复，不将浏览器验证替代真机通过。
