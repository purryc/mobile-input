## 文本框激活动效

平板新建任务及任务详情的输入框复用微信的青蓝／淡紫珠光：显式点击或键盘聚焦触发两次 240 ms 闪动，随后 2000 ms 玻璃扫光；已连接且仍是当前编辑目标时保留 4 秒一圈的细流光。只包围输入框，不包围外层页面或工作空间／权限区域。

手机仍立即显示真实编辑目标；动效不阻塞输入、不提交任务、不引入演示文稿预设。普通草稿同步不重播，目标变化或断线停止；减少动态效果设置下使用静态描边。

动效验证：浏览器确认两次闪动／扫光节点、激活后的持续边框、草稿同步不重播、重复点击重播以及断线停止。现有 3 项 WorkBuddy 输入回归与生产构建通过；两端签名包覆盖安装成功，热点重新配对后在 MRDI-W10 新建任务输入框核对了真实渲染（`artifacts/workbuddy-focus/device-focus.jpeg`）。

## 点击输入框唤起手机

输入框本体及留白区域现在都作为显式入口：点击会同时播放流光并向平板权威状态重新声明当前编辑目标，手机进入对应的新任务草稿页。即使浏览器输入框仍持有 DOM 焦点，目标被取消后再次点击也会重新激活；无需先点别处。再次激活保留草稿，不创建任务，也不自动发送。添加附件、模型和发送等工具按钮保留各自动作。

入口回归：空白边距点击会显示手机输入；权威目标取消而 DOM 仍聚焦时，重点击可恢复；release 后 unknown 焦点可恢复为 editable；原草稿保留、任务数量不增加。现有 3 项 WorkBuddy 输入测试、类型检查与两端生产构建通过。检查脚本及记录在 `artifacts/workbuddy-entry/`。

本轮两端签名包覆盖安装与热点配对成功。MRDI-W10 在新建任务输入框的左侧留白（原生坐标 1000,870）点击后，手机实际显示“新建任务 草稿”和“手机 WorkBuddy 草稿”输入框；原生 UI 树见 `artifacts/workbuddy-entry/device-phone.json`。

## 所有任务按意图出现绘画／调色工具

删除共享任务输入框底部常驻的画笔和调色板按钮，覆盖新建任务、已有任务及切换恢复的任务。单纯打开或聚焦不创建任何颜色／草图参数。识别完成后的明确颜色／布局意图仍通过现有规则显示调色或手绘面板；已有参数和已确认草图附件仍可继续编辑，并按任务隔离。票据、采集、发送及固定输入工具区保持原有行为。

验证：类型检查、95 项核心测试、5 项自适应输入／紧凑布局浏览器测试、Web 与两端签名构建通过。浏览器语音事件测试确认中间转写不触发工具，完成后才推断；不作为本轮真人语音证据。两端覆盖安装并重新通过热点配对，手机原生 UI 读回确认常驻“手绘布局／主色工具”按钮已移除，既有含布局要求的草稿及其手绘面板保留。本轮未重复真人语音及拔线验收。日志在 `artifacts/workbuddy-intent-tools/`。
