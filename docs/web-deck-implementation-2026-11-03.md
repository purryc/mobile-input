# WorkBuddy 网页演示：固定输入控件与 Gemini 执行

更新：2026-11-03。本文记录代码和验收，不替代 Notion Design/Survey 的主规范。

## 本轮结果

fake WorkBuddy 首页增加「生成网页演示」。输入侧采用固定短语规则，引用现有句内 token、资料选择、照片、调色、手绘、时长和 InputDock。界面结构由已登记组件确定，不由模型生成。Laya 的服务端 worker、安装脚本、Python 依赖、分析协议和前端调用已移除；历史记录及忽略目录内缓存保留。

明确点击发送后，浏览器开发版由 Mac 服务调用 Google Gemini；原生 HAP 已扩展为平板直接调用（见[独立运行记录](web-deck-native-standalone-2026-11-03.md)）：先理解用户实际画出的草图，再结合所选文件、照片、明确颜色和时长生成页面。OpenUI 使用登记的 DeckPage 组件渲染经校验的数据。生成与停止均有任务状态；失败保留提交快照，可显式重试。旧的确定性演示任务继续使用原流程，网页演示不会由旧计时器假装完成。

## 启动与入口

1. 项目根目录执行 `npm run dev`，开发服务器同时提供前端与 `/api/decks/*`。已有服务运行时无需重复启动。
2. 打开 `http://localhost:5188`，进入 WorkBuddy → 生成网页演示。
3. 可输入：`参考产品资料，添加实拍照片。背景用灰色，主色用红色，文字用黑色。产品展示页布局我画一下。讲十分钟，做四页。`
4. 点击对应句内入口选择实际材料、调色、手绘并采用，最后发送。未画任何笔迹时不会制造草图。未采用草图需先采用或清空才可发送。
5. 完成后打开网页演示，可编辑标题、正文、讲稿、颜色、布局、照片及裁切方式；可增删排序、撤销/重做、保存和播放。输入「本页修改要求」只让 Gemini 改该页文字；返回时若页面已经改变，不覆盖手动修改。

Web 双端沿用原 LAN 配对方式。两端浏览器访问同一 Mac Web 服务，手机使用 `?role=phone`。新结果已接入手机演讲者视图和上一页/下一页/退出命令；原生 HAP 已实现独立资产传输与平板直连 Gemini，详见[原生独立运行记录](web-deck-native-standalone-2026-11-03.md)。原生接口模拟、编译和实际设备验收分开记录。

`npm run deck:service` 可单独在 Mac 回环地址 5192 启动 API，生产静态前端需要同源反向代理 `/api/decks`。仅复制 `dist/` 不含服务，不能调用 Google。

## 浏览器开发版凭据、材料与执行边界

- 采用用户指定 `Google API.md` 中的凭据，保存在忽略目录 `artifacts/web-deck/google-api-key`（0600），也支持服务进程的 `GOOGLE_API_KEY`。原输入文件加入 Git 忽略。浏览器、构建产物和日志不包含密钥。
- 默认 `gemini-3.8-flash`，当前凭据的模型列表及真实多模态生成均已验证。`INPUT_AGENT_DECK_MODEL` 可由服务环境显式替换，不能从浏览器传任意模型或服务地址。
- 支持 PDF、TXT、Markdown、PNG、JPEG、WebP；单文件 8 MB、最多 12 件、总计 24 MB。不支持 DOCX/PPTX/XLSX 原生解析，不把输入里的路径视为已上传文件，不自动抓取网址。
- 输入材料保存为服务端 UUID 文件。只发送本任务已采用的材料，错误、取消或采用都不会自动发送任务。服务没有任意路径读取、任意 URL 获取或命令执行接口。
- 当前为可信局域网开发服务：同源请求检查和容量限制已实现，尚未实现面向公网的账户、配额或多用户资源隔离。不要把此开发端口当作公网服务。
- 图片和草图用真实字节进入模型；命名页与照片范围、用户选定 HEX 颜色在服务端校验/约束。草图映射为 6 个已登记布局（封面、左图右文、左文右图、上下排列、卡片、大图），不承诺任意草图的像素级复刻。草图需明确目标页名；无法绑定会提示修改需求后重试。
- 时长影响内容组织及讲稿，未用语音实测演讲时长。文字仍需用户检查事实和版面。当前文件为应用内持久化的结构化网页演示，可编辑和浏览器播放；尚无独立 HTML/PPTX 下载导出。
- 确认生成请求后清空下一份输入；原提交的文本、参数和材料存于任务快照。未完成草图随原任务保存，材料选择异步返回仍归属原任务。演示重置沿用既有范围，真实 Mac 任务和文件不受影响。
- 停止/重试/任务恢复改变执行代次；旧响应不能落入新任务。只允许执行端确认生成结果。现有文件工作副本、保存冲突、撤销/重做用于网页演示，AI 更新携带版本检查。

## 验证与可复现证据

- Google 真实调用：仅发送虚构产品 TXT、项目自带测试插图及测试绘制草图，无个人材料。两次成功生成 4 页，分别约 24.2 秒和 17.8 秒；绑定指定照片，产品展示页采用 `image-left`，四页背景/主色/文字颜色分别为 `#D9DEDF` / `#C92A2A` / `#182431`。仅代表这两次请求，不是稳定延迟承诺。
- `npm run test:deck:live`：显式联网的可复现测试，使用同一类测试材料，会消耗 API。输出位于忽略目录 `artifacts/web-deck/live-smoke.ndjson` 和 `live-smoke-deck.json`。
- `npx tsx --test packages/core/web-deck.test.ts`：6 项通过，涵盖规则、提交快照、停止/重试、旧结果拒绝、保存/撤销、作用范围、未完成草图。
- `npx tsx --test scripts/web-deck-service.test.ts`：2 项通过，模型调用使用桩；覆盖跨源/不支持格式/坏参数拒绝，以及照片、草图、颜色约束。不能作为真实模型证据。
- `npx playwright test tests/web-deck.spec.ts`：生成结果用固定响应，覆盖编辑保存重开、播放、停止、WebSocket 配对手机参数同步、草图保留及 390px 输入区边界。见 `artifacts/web-deck/browser-editor.png` 与 `browser-phone-sketch.png`。
- 全量 core、Mac 协议测试、TypeScript、生产构建和受影响浏览器回归结果见本节末的最终检查。
- `tests/workbuddy-adaptive-input.spec.ts` 的 3 个旧用例仍等待已被 2026-10-20 规则取消的「开始使用」弹窗，未进入其后续断言；此次未把旧测试改写成新功能验收。没有手机/平板安装、真机调用或演讲时长验收。

## 文件地图

- `packages/core/live-workbuddy.ts`：共享固定规则、明确值与源位置。
- `packages/core/web-deck.ts` / `workbuddy-deck.ts`：数据校验、原任务归属、版本和执行状态。
- `apps/web/src/web-deck-composer.tsx`：固定句内入口与材料采用。
- `web-deck-view.tsx` / `web-deck.css`：登记组件、编辑器及演讲者视图。
- `web-deck-api.ts` / `web-deck-runner.ts`：材料上传、流式状态、取消与迟到响应处理。
- `scripts/web-deck-service.ts`：凭据读取、Google 多模态请求、校验与私有资产。
- `apps/web/index.html`：禁止 OpenUI 1.0.2 的开发检查器自动挂载，避免遮住手机操作区；依赖已锁定，升级需检查这一兼容点。生产构建也不显示检查器。
