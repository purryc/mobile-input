## 1 判断与统计口径

**主要继承 Windows 用户习惯，执行则遵循鸿蒙 PC 自己的版本化键位。** TMG 2022-06-06 纪要 P14–P15 明确写“遵循 Windows 用户习惯优先”，目标用户与迁移用户主要为 Windows 使用者。P12–P13 规定系统键组合由系统独占；P16–P17 的“至多3个键”是一次组合键包含的物理键数，不是手机面板最多三个按钮。Mac 一列用于比较，不是主要目标，也不能把 Command 全局映射成 Ctrl 后就认为对齐完成。

原表共11张工作表。以下完整列出两个可见操作表：主表429行、第三方表222行，共651行。隐藏的历史快照与支持率表不重复累计；可见“数据验证字段”为组织字段。主表31个应用/系统/框架分组，第三方表51个应用，其中36个只有名称。总览82行是分组数，不等于82个独立应用。651也不是去重命令数或使用次数。

## 2 通用层应分成三类

系统全局入口、文本编辑、焦点导航互相独立。Ctrl+C虽然常见，仍取决于当前文本/文件/图片等对象，不能称为任何应用任何状态都可用。

| 层 | 原表新PC中的典型绑定 | 面板位置建议 |
| --- | --- | --- |
| 系统与窗口 | Alt+Tab切应用；Logo+S搜索；Logo+F文管；Logo+L锁屏；Alt+F4关闭；Alt+Shift+F4退出 | 固定系统入口与二级面板，不随应用重复生成 |
| 系统捕获 | Logo+Shift+S区域截屏；Logo+Shift+R录屏；PrtSc全屏截图 | 系统/材料入口复用，勿占满应用主区 |
| 文本编辑 | Ctrl+C/X/V；Ctrl+Z；Ctrl+Y或Ctrl+Shift+Z；Delete | 已有共享编辑区；只作用于已确认对象 |
| 文本定位 | Ctrl+↑/↓段首尾；Ctrl+Home/End文档首尾；↑/↓前后行 | 选区或编辑模式下扩展，不默认常驻全部键 |
| 文本定位待补齐 | Ctrl+Shift+←/→选词；Fn+←/→行首尾；Ctrl+←/→前后词（SR20240112398433） | 可纳入未来文字编辑能力组 |
| 焦点导航 | Tab/Shift+Tab；Enter/Space激活；Esc取消；方向键；Shift+F10菜单 | 通用输入层，根据文本焦点与弹窗状态解释 |

主表同一文本动作重复于多个应用，不意味着应在自适应区重复画一遍。全选在多应用条目中出现，但ArkUI块没有独立全选行，不能据此宣称该框架块已验证全选。框架能力末尾仍有未完成项，Enter等基础键也需要目标版本与具体页面验证。

## 5 产品管理视角：什么值得进入首屏

本轮使用已安装的 analyze-feature-requests 技能做任务归类与验证优先级，没有名为pmskills的独立入口。未收集重要性、满意度或真实频次数据，因此不编造Opportunity Score。

1. **先完成基础文本与对象编辑的一致性。** 覆盖广，复用现有固定编辑区，投入小。风险是文本撤销、文件撤销和删除恢复同名不同能力。先在文管与文字编辑中验证焦点变化，不把同键视为同作用域。
2. **再验证模式明确的专用操作组。** MindMaster节点结构、浏览器导航/查找、文管浏览/选择有可表达的任务差异。收益在于少记键位、少找菜单；需测任务完成时间、误操作、恢复和低头次数。只增加目录与适配、不写专用整页UI，是生成能力的关键验收。
3. **将有单号能力作为目录演进计划。** 61条补齐候选进入设计清单，运行时仍由版本能力开关启用。高风险假设是“单号最终兑现且键位不变”，最小验证是固定版本抽查；不按单号数量评价产品价值。

优先级看“当前任务是否需要、相对大屏操作省多少、是否反复使用、是否易误触、是否已有固定入口”，不按一个应用原表行数排。WPS有73行，演示播放核心仍只有3个语义动作；Coremail7项全支持，依然不足以得到专用邮件面板。

## 6 Product Design视角：自适应区到底放多少键

**建议默认4–6个可点目标；键盘/触控板展开或空间紧时3–4个；用户主动展开时可到8个短标签目标。** 这些是结合现有390px手机布局提出的待验证设计参数，不是由快捷键表证明的人体工学最优值。

先分清三个数：快捷键绑定数、语义动作数、屏幕点击目标数。前进动画的Enter/Space/↓/→是4种绑定、1个动作、1个按钮；字号增减可做1个Stepper组合，但有2个点击目标。更多入口也占1个目标。固定编辑区、语音、切应用仍计入整屏操作密度，只是不算自适应区新增键。

以390px逻辑宽度、左右各18px留白得到354px内容宽，列间隔8px：

| 布局 | 单格宽 | 假设高度64px时内容高度 | 适用 |
| --- | ---: | ---: | --- |
| 2列×2行 | 173px | 136px | 4键，长中文标签、主动作 |
| 3列×2行 | 112.7px | 136px | 6键，默认短标签 |
| 4列×2行 | 82.5px | 136px | 8键，仅短标签或熟悉图标，主动展开 |
| 3列×1行 | 112.7px | 64px | 3键，播放/紧凑状态 |

以上还未计组标题、上下内边距、上下文、输入框、安全区；每个触摸目标至少48×48。可用行数按floor((剩余高度+8)/(64+8))算，先扣除固定底栏与编辑空间。不得挤压Send、语音或文本编辑区来凑够6键；不够时减少候选或进入更多。专业旋钮/连续控件按剩余空间选择L/M/S，不能为了达到6键把大旋钮强塞进小按钮格。

规律与落地规则：

- **三层不混。** 系统常驻入口、固定编辑区、自适应专用区各负其责。
- **一个模式一组。** 阅读/编辑、浏览/选中、节点/节点文字、演示编辑/播放分别选键。
- **稳定核心，局部替换。** 主动作和用户固定项位置稳定；状态明确变化才换组。按住或拖动期间锁定布局。
- **成对动作成组。** 上下页、前后结果、增减字号保持相邻；不同业务的添加/删除不当作数值增减。
- **首屏不凑满。** 只有3个有用动作就放3个；只有通用编辑能力就新增0个。
- **动作与状态区分。** 无格式回读时是动作按钮；拿不到字号/进度当前值时不画可设定的绝对滑杆。
- **风险不同位置不同。** 删除、终止进程、退出放次级入口；发送保留明确动作和当前目标，不混入无条件快捷连按。

## 7 对任意应用生成面板的实际含义

接入时读取该应用真实命令/快捷键目录，保留平台、版本、作用域、来源和计划。语义归一之后按上下文选取小集合，映射现有原子控件，再组合输入和场景层。产品的可扩展性来自数据与适配复用，不是给每个应用重新写页面。

存在原生预设时继续用预设。新应用只有快捷键列表时可先生成候选；确认目标版本与执行通道后启用。仅知道应用名字无法可靠推导命令；36个空目录需要补真实能力，不能按行业常识生成看似可用的按钮。

本轮新增全量清单与规划解读，不修改运行时、Figma或上轮研究预览。没有把文档研究升级成设备接入验收，没有向外部模型发送源文档，没有上传或Git push。
