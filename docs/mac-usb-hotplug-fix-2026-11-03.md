# USB 热插拔自动回切修复 · 2026-11-03

## 事实与修复

用户确认原生 ⌘Tab 连续切换正常，但 USB 重插未自动回切。检查时 HDC 已识别手机，桥接映射却为空。模拟复现确认：设备类型读取返回失败正文时，旧实现将其缓存成非手机，后续不再读取或创建映射。未取得故障当时的设备读取记录，不能断言这是该次真机失败的唯一原因。

本次处理：
- 仅缓存明确识别的设备类型，10 秒重新确认；读取失败或未知输出持续重试，设备离线清除缓存。
- 将 HDC 的 `[Fail]` 正文视为失败，即使进程退出码为零。映射创建后重新查询，按设备、端口、Reverse 方向精确确认；不修改其他映射。
- 区分 USB 检测、映射确认和已认证会话；本地连接页不将“检测到设备”显示成通道就绪。
- 原生未确认命令最长等待 5 秒，超时关闭旧通道并走现有自动恢复，保留结果未知语义，不重放命令。过期回执和旧通道事件不能影响新连接。
- USB 接管前暂停 Web 写入；认证接管后重新接收权威状态。保留同一逻辑会话、配对、草稿、材料和回执，不提交任务。
- Mac 记录阶段变化，单进程上限 256 条；手机记录固定阶段代码，每种至少相隔 30 秒，总上限 128 条。不输出凭据、文本、文件内容或设备标识。

## 验收与证据

保持手机在前台、两端同一热点。每轮拔线后等待“无线”，插回后等待“USB”，无需重新配对。目标为系统识别设备后空闲情况下 5 秒内自动接管；连续三轮确认，补查草稿保留、触控板及原生 ⌘Tab。人工插线到系统枚举耗时与应用接管耗时分开记录。
