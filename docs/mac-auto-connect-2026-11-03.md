# Mac 自动重连与二维码入口 · 2026-11-03

## 使用方式

- Mac 的 `~/Applications/Input Agent 连接.app` 打开本地连接页 `http://127.0.0.1:39873/`。桥接服务注册为用户登录启动，不依赖终端窗口。
- 首次在手机 Input Agent 选择“Mac 应用”，扫描 Mac 页二维码完成配对。更新前仅存于内存的旧配对需要重新建立一次。
- 已配对后，手机处于前台且当前目标为 Mac 时自动重连：先 USB，后此前配对的无线地址。USB 需要数据线与已授权的 USB 调试；不会自动启动锁屏或后台手机应用。
- 手动断开停止自动重试；切目标或后台暂停，重新回到 Mac 前台后恢复。连接成功后的第一份权威状态到达前不发送操作；重连不重放文字或任务提交。
- Mac 网络地址变化时重新扫码。连接页每 20 秒刷新当前网络、短期配对码和状态；Wi-Fi 需手机能够访问 Mac，企业访客隔离不能靠二维码绕过。

## 实现与隐私

- Mac 身份与信任保存在用户 Application Support/Input Agent/mac-trust.json，目录 0700、文件 0600。手机信任保存在本机 Asset Store；Web 只保存地址和自动重连开关，不获得原生恢复凭据。
- 同一手机进程在 USB/无线切换时保留会话；Mac 或手机进程重启创建新的命令会话，避免旧序号/回执污染。
- 配对页面只监听回环 39873；网络控制端口 39872 的 HTTP 请求返回 404。二维码只含短期配对码，不含恢复凭据。
- Mac LaunchAgent 为 `com.hmilab.input-agent.mac-bridge`。需要停止自启时可运行 `launchctl bootout gui/$(id -u)/com.hmilab.input-agent.mac-bridge`，再移除对应 `~/Library/LaunchAgents/` plist。应用入口和服务配置均不改变真实文档。
- 现有 Mac 辅助功能权限仍须有效。服务启动不代表已经获得应用读写权限或手机已连接。

## 验证分层

- 类型检查与生产 Web 构建通过；手机 ArkTS 编译、签名 HAP 构建通过。
- Mac 单元测试 13 项通过：私有信任持久化、文件权限、USB 路由、协议及二维码输出。
- 核心测试覆盖原生凭据保存/重启恢复、凭据不下发 Web、USB 回退和同桥接路由切换。
- 浏览器模拟覆盖启动恢复、断线重试、显式断开停止、两种 Mac 输入场景自动文本同步；不等于真机验证。
- 本机已安装 LaunchAgent，确认运行；连接页 HTTP 200，控制端 HTTP 404，连接页可见二维码和 USB 通道状态。
- 用户授权后，已将签名 HAP 安装至 SUP-AL90 手机并启动。首次配对后设置页明确显示“Mac 已连接 · USB”。强制停止并重新打开手机 App 后自动恢复 USB；重启 Mac LaunchAgent 后手机再次自动恢复 USB，Mac 端确认有已认证手机连接。全程未发送任务或修改 Mac 文档。
- 发现独立 LaunchAgent 启动后，Mac 权威状态返回辅助功能权限未获准，手机显示“允许辅助功能”。这不影响已验证的认证/传输连接，但鼠标和文字控制尚不可用，需用户在 macOS 隐私与安全性中完成桥接进程授权；本轮未修改权限，也未将连接成功报成控制成功。
- Wi-Fi 拔线回退、真实相机扫码与重新插线升级仍待用户配合验收。证据保存在 `artifacts/mac-bridge/device/auto-*.json/png`，不提交私有截图。
- 本轮不推送 GitHub 或上传 Drive。
