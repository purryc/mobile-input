# Mac 原生应用切换与 USB 自动优先 · 2026-11-03

## 行为

- 手机 Codex、WorkBuddy、WPS 和未适配应用页共用“切换 Mac 应用”按钮。点击发送有身份和回执的 `app-switch/next`，Mac 显示系统 Command-Tab 切换器；每次点击前进一项，最后一次点击后 1200 ms 释放 Command，进入高亮应用。
- 列表由 macOS 管理。切到未适配应用仅改变前台，不开放任意文本或指针控制。真实文档与任务发送权限不变。
- 原生独立计时器负责释放，避免 AX 状态扫描或等待网络阻塞 Command 松开。断线、后台、显式 release、锁屏和正常进程结束取消切换并释放；重复命令不会重复跳格。切换期间收到普通控制命令先取消切换并拒绝该命令，避免把文字当成 Command 快捷键执行。
- 已配对且手机在前台时 USB 自动优先。Mac 每秒检查一次授权手机及本桥接反向端口，手机在空闲心跳上每 1.5 秒探测一次 USB；同一桥接身份验证后自动提升连接，按键按住或命令待回执时延后。不同 Mac、未授权 USB 不接管。
- 同一会话的草稿、材料和回执保留；未知执行结果不重放。物理热插拔耗时还受系统 USB 枚举影响，检测周期不等于真机延迟承诺。

## 验证

- TypeScript 检查、生产构建通过。
- 核心测试 170 项通过，包括新 USB 探测间隔和现有同桥接提升、断线回退、按键保护。
- Mac 测试 15 项通过，包括原生切换器的连续点击、过期计时器、提交、取消及幂等释放；测试注入按键回调，不把单测当作系统 UI 验收。
- 浏览器 2 项通过：四个 Mac 页面使用同一切换命令且不修改/提交草稿；原生信任自动重连回归。
- Swift 原生编译、手机签名 HAP 构建与 SUP-AL90 安装启动通过。Mac LaunchAgent 已更新；恢复配对后手机有可用指针控件，不再显示此前的辅助功能阻断。
- 真机点击手机“切换 Mac 应用”后，权威状态从 Codex 变为 WorkBuddy；后续观察时前台已变为未适配应用，不能据此宣称长时间稳定性。未发送任务或改写文档。
