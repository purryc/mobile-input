# Slides 叙事整理：设备厂商系统输入能力

2026-10-19。以在线Figma实际23页、现行PRD及已确认OEM定位为依据。Claude CLI实际模型claude-opus-5-5在禁用工具会话中独立审阅全文；Codex检查在线页序、可见文字与关键页截图，负责取舍和修改。未做设备、模型或商业验证。

## 判断与取舍

- 原2–5页提前进入技术规格；背景在6–8页。改为问题与买方→体验→生成机制→验证。
- 原8页个人付费假设与厂商采购定位冲突；改为终端收益、系统交付和采购条件。
- 原2页五题、原5页六类与现行七类不一致；主讲总览讲三条路径，完整七类进入附录。
- 原10页为整张架构图片，缺少能力目录与PanelSpec；保留隐藏原图，用可编辑数据流和逐帧例子说明生成过程。
- 原18页剪辑是已绘制设计稿；只用来说明目标界面，不宣称由模型实际生成。新增任务相关性对照也标设计预期。
- 不采纳Claude把所有应用统一标“均未接入”；按图片/能力区分官方参考、内部演示与待接入，不抹掉已有证据差异。
- 不采纳“否定句只有模型才能处理”的推断：现有规则也可覆盖，模型增量需规则对照实验。
- Claude建议15页主讲、单独新增审阅页；采用14页主讲、9页附录，Demo前置，任务介入留主线，审阅分歧记录在本文和讲者备注。

### 2026-10-20：按真实输入条件修正第3页

- 文档人群：大量文字输入是核心负担。展开态用小悬浮键盘或外接物理键盘；折叠态可使用下半屏虚拟键盘。补充携带／摆放、触屏持续输入与嘈杂环境下语音的限制。换掉展开大屏显示大面积虚拟键盘的错误情境图，按官方星跃随行键盘外观生成独立键盘办公情境。
- 专业创作人群保留，继续讲工具查找与连续操作被打断。
- 第三类明确为“多项目、多线程 Agent 协作者”：跨平台界面切换、指令输入和多模态材料加入任务的负担。第4页同列对应改为统一输入及按任务补充，限定已适配 Agent。
- 娱乐人群补充配件携带、笔遥控的控制范围，以及虚拟键盘和大屏两侧触控对游戏连续操作的限制；配图换为双手伸向展开大屏左右下角的游戏情境。

事实与假设分别记录：

1. [华为展开态说明](https://consumer.huawei.com/cn/support/content/zh-cn16048766/)明确展开态支持物理键盘／小键盘，不支持下半屏虚拟键盘。[折叠态说明](https://consumer.huawei.com/cn/support/content/zh-cn16048768/)说明折叠态的虚拟键盘用法。
2. [星跃随行键盘](https://consumer.huawei.com/cn/accessories/xingyue-portable-keyboard/)具有独立薄型键盘和触控板。已目视检查官方蓝色配件图，保存在本轮 artifacts，生成图只是情境示意。
3. [M-Pen 3 官方说明](https://consumer.huawei.com/cn/accessories/m-pen-3/)列出三个按键，空鼠模式支持指向及上下翻页。因此不采用“只有两个按键／只能指向”的事实断言。
4. Survey 原文 `sources/voice-input-research.md` 支持长上下文提示仍需要文件、选区、截图或项目状态，以及共享空间／噪声的使用边界；主报告的 Codex Micro、Vibe Key 研究提供任务状态、切换和输入控制案例。原报告也明确“本次语音样本没有直接多 Agent 需求量证据”。跨平台高频程度、触屏输入慢的幅度、大屏游戏操作成本，仍是本项目待测痛点，不能写成已完成用户研究结论。
5. 手机输入也可能遇到噪声、触屏打字和视线切换问题。第3页提出需求，第4页表达方案方向；尚未证明手机能全面替代长文物理键盘或带来净效率收益。
