# WorkBuddy 独立文件窗口与手机协同：第二批 PRD / 协议

## 目标与已授权范围

延续 `workbuddy-mobile-approval`，保留主窗口销售链、独立手机任务、计划确认和分享审批。手机提交一个固定销售 PPT 演示任务后，在文件窗口看真实可改的对象；手机指向对象，输入或使用明确标记的演示语音转写，核对预览，确认应用，再撤销当前文档的修改。不接真实 WorkBuddy API、付费模型、原生语音、任意 PPTX 解析、OS 默认打开方式或真实分享。

## 官方事实（2026-10-10 实际读取）

- [独立文件浏览器](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/File-Browser)：独立窗口、多标签、拖动排序、加号菜单、最近文件；AI 栏默认收起，宽度可调，上下文跟随文件。Office 手动保存，关闭提示；Markdown 自动保存。保存到原文件是官方桌面行为。
- [人机双写](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Knowledge-Base/Cowriting)：PPT 可点选、框选和整页选择，通过绿色 AI 编辑入口提交引用与指令，支持撤销重做。
- 手机触控板、冻结选区的语音草稿、先预览后确认是本原型的设计扩展。版本 5.7.7 不作为文件浏览器首发版本证据。不推测用户提及但未确认的模型名称。

## 本轮交互

1. 手机新建任务选择「可编辑 PPT 演示」，输入主题。使用固定三页销售模板与现有虚构产品数据，主题改变封面文本，完成回执包含任务与文件。
2. 文件窗口拥有自己的标签、页缩略图、画布、显式保存态和可收起 AI 栏。主窗口旧预览保留，可显式进入文件窗口。浏览器可打开一个复用的真实附属窗口；弹窗受限时保留工作台内文件窗口。附属窗口通过同源 opener 通信，不建立第二个执行器或桥连接。
3. 手机「编辑此 PPT」上部展示当前文件、页和所选对象，支持选页/对象列表、触控板点选或框选；下部输入、演示语音、预览/确认位置固定。语音仅本地模拟转写，开始时冻结选区；从此切换对象不会改变草稿归属。
4. 支持确定性指令：`改为：文字`、`改成蓝色/绿色/黑色`、`字号 28`、`向右/左/上/下移动 40`。不支持的指令明确失败，原文档不变，不伪造模型成功。
5. 预览优先显示「本次修改」的冻结对象、所有实际变更字段和带选区边框的前后画布；手机暂收起指向区域与输入要求，差异可在固定确认栏上方滚动查看。当前指向与冻结对象不同时明确提示，不自动改目标。「重新选择对象」展开指向区域并禁用应用，显式重新锁定保留文字、取消旧提案后必须重新预览；可返回原预览，不设置强制滚动门槛。确认只应用冻结目标，取消/Back 保留文字并使预览不可执行。文件或页切换时不丢稿，返回原页核对后方可预览/应用。新建任务的成果类型、模式和手绘阶段在手机独立键保留，返回后需重新核对节点确认；创建 payload 由核心校验。
6. 应用改变工作副本，Office 显式保存才更新本地演示文件；未保存关闭可保存/放弃/取消。Markdown 自动保存。普通 Word / Markdown 仅纯文本演示，表格和旧 PPT 是只读预览。本地保存为浏览器存储，无磁盘覆盖承诺。
7. 撤销/重做仅操作该文档的内容快照。每次回退仍增加文档 revision，旧预览不能复活。全局 Store.undo 不参与；其他任务、草稿、审批和分享记录保持当前状态。

## 权威数据与协议

`packages/core/workbuddy-documents.ts` 是受控对象、文件窗口和编辑协议的权威。`fileWorkspace.version = 1` 为 WorkBuddy v2 的附加子模型；首次升级先备份旧 WorkBuddy，失败阻止写入，旧字节保留。文档持久化工作副本、已保存副本、sourceRevision、单调 revision、undo/redo、初始演示副本、独立草稿、提案。可撤销的 PPT 演示重置只作用当前文档。页面和对象 ID 稳定；几何为 960×540 画布坐标，不复用旧只有 title/body/notes 的 Slide。

选择引用含 fileId/documentRevision/pageId/objectIds。输入草稿另有 draftId/targetRevision/value.revision/session/sequence。指针包含 pageId/documentRevision/pointerEpoch/gesture/sequence；切页、切文件、断连或后台释放增加 epoch，迟到消息不能再次选择。非持久的指针移动只转消息，不执行修改。

创建、预览、应用、撤销、重做、保存和关闭使用持久 operationId+payload signature，兼容已有 `operations` 回执。相同操作重试回原结果，复用 ID 改 payload 拒绝；成功副作用与回执同一 core 状态提交。预览含每个对象 before/after，应用检查当前文档版本、对象仍存在、前值一致、提案仍 pending。不得从 wb-submit 的追问新 task ID 补原任务或审批。

草稿与待确认操作保留在手机独立键，断连保留文本，重连显式恢复；回执丢失复用原 payload，不生成新执行。另一个文件被旧编辑器修改时，sourceRevision 冲突阻止覆盖；显式放弃并重新打开载入新版本。

取消/Back 在回执未到时先保留本端最新文字并停止排队输入；本地取消标志仅用于恢复入口，不代替核心执行结果。断线时也可返回并保留草稿，重连恢复先结束旧草稿，再使用原 fileId/pageId/objectIds/documentRevision；不采用取消时碰巧选中的其他对象。未同步或本端取消的文字优先保留；已确认的旧缓存不覆盖工作台后续输入。原文档版本变化时保留文字并拒绝自动绑定，预览与确认仍由核心校验。

## 验收

- 新增核心测试覆盖冻结对象/顺序、过期版本、重复执行和重载、取消、指针 epoch、多对象几何、保存冲突、局部撤销、迁移失败。
- 浏览器验证手机→任务→PPT→触控板/演示转写→前后预览→确认→保存→撤销；标签切换不串上下文，附属窗口不抢配对，关闭警告，离线保留并恢复。
- 跑 check、全部核心测试、production build、第一批六条浏览器测试及既有回归。既有四条失败单独记录，不修改源码以规避。
- Figma 由父设计任务维护，本代码任务不编辑 Figma。分支提交/推送已获本轮明确授权；禁止 main 合并、强推、PR、公开部署或改共享权限。

## 已确认的追加故事与示例选择

- 手绘 Roadmap：用户明确要求由手绘图创建路线图 PPT。本轮内置 SVG 手绘示例，点击「读取示例手绘节点（模拟）」得到四个可编辑阶段，用户核对名称/日期后确认生成。节点文字真正进入同一受控 PPT 对象模型，可继续改文字、颜色与几何，撤销仅当前文档。四个阶段及日期是演示选择；不提供通用图片理解、OCR 或真实相机权限。
- 补传收据：用户原文要求「整理今年收据的，少了几个月的票据，然后用户可以上传票据从手机上」。因此在 PPT 演示创建时建立一个独立的后台示例票据任务，通知缺少 2/5/9 月材料。手机从通知进入「拍照（示例）」或「上传附件（示例）」，仅使用内置虚构票据，核对/修改日期、商店、项目与金额，再补充到**同一个**任务。表格记录实际保存，本轮为本地 CSV 数据与表格视图；取消不提交，重复确认不重复入表，支持重置演示。月份/字段和金额不是用户强制需求。返回 PPT 保留原页、选区、文字和未应用预览，不把补材料变成新 task。

每次补充一个示例票据；实际核心记录返回后显示「最近补充 1 张，已整理到原任务」与当前总数，重置后消失。此状态取自已整理记录，不把点击或发送命令视为完成。

## UX 研究依据与未验证事项

父研究任务提供的资料与本轮核读原始来源支持以下设计推论，均不等于本产品真人测试：

- [Oviatt 等，CHI 1997](https://chi1997.acm.org/proceedings/paper/slo.html) 分析了顺序与同时的多模态输入。因此默认先选中、点击演示语音后冻结引用，不要求同一拇指持续移动并按住录音。文字和对象列表提供非语音、非拖动替代路径。
- [Parhi 等，MobileHCI 2006](https://www.cs.umd.edu/~bederson/images/pubs_pdfs/p203-parhi.pdf) 研究单手拇指目标选择；[Vogel / Baudisch，CHI 2007](https://www.patrickbaudisch.com/publications/2007-Vogel-CHI07-Shift.pdf) 讨论触屏精细选择。固定底部动作、留间隔、大热区及上下文选择列表是本原型的设计推论。平台的 iOS 44pt / Android 48dp 指导不可机械等同于 CSS px 或宣称真机可达。
- [Altmann / Trafton，CogSci 2004](https://interruptions.net/literature/Altmann-CogSci04.pdf) 研究中断恢复与提示。票据切入保留原 PPT 文档/页/对象/版本与草稿，返回明确提示恢复；版本变化禁止悄然修改新对象。

Web 使用响应式上下分区、safe-area inset 与已有 native-insets，不画 Home 条充当安全区。预览/应用固定在下部动作位置，中间内容滚动。锁定引用始终可见，允许显式按当前选区重新锁定并保留文字。未来建议 8–12 名受试者，覆盖左右手、单/双手和不同屏幕，测试可达性、误触、提示理解及恢复时间；本轮只有云浏览器验证，没有真人/真机证据。
