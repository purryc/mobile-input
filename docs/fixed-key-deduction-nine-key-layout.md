# 固定键扣除与九键自适应区

> 后续设计修订：同日用户确认改为 12 格（11 个操作＋固定“更多”），新增长按整理与溢出回收。当前 Figma 规则见 [12 格布局记录](nine-key-layout-placeholder.md)。下文保留九格阶段的研究计算，不再作为最新容量上限；固定编辑键扣除结论仍适用。未修改运行时。

2026-10-20，依据用户新要求复核。范围是当前共享底栏代码与此前已整理的原表新PC列、单号、计划；不改运行时、不重画Figma、不覆盖原件或既有Excel。本页更新上轮“默认4–6键、展开最多8键”的研究建议：**以3×3、最多9个点击目标作为新的研究方案，按实际任务填充；模式切换或空间不足时减少显示。** 这是容量方案，尚非实机可用性结论。

## 当前固定区实际有哪些键

| 部位 | 入口 | 数量 |

| 固定编辑行 | 全选、复制、剪切、粘贴、删除、撤销、重做 | 7 |
| 同行采集入口 | 采集方式 | 1 |
| 收起时底行 | 键盘、触控板、智慧语音 | 3 |
| 收起状态合计 | 不含顶部连接/切应用，也不含已打开采集子菜单 | 11 |
| 展开触控板 | 上述11个，加左键、右键 | 13 |
| 展开键盘 | 上述11个，加空格、回车；字母/符号键盘另计 | 13＋键盘内部按键 |

搜索、多任务、Esc及四个应用入口位于桌面控制器，见[phone-desktop.tsx](../apps/web/src/phone-desktop.tsx)，并不是每个应用都固定显示。因此不能把所有应用的查找、取消都按“已有固定键”扣掉。普通键盘的回车实现是插入换行，不能当作应用里的“确认”“发送”“添加分支”已被覆盖。

本轮扣除集合只有七类编辑动作。采集入口不自动等价于OS全屏截屏/系统录屏；普通Delete不等于永久删除、终止进程、确认删除，也不等于文字删除线。

## 计数方式与结果

沿用上轮口径：H列√、L明确已支持、有真实单号且未明确排除、有明确计划无单号，均进入产品设计候选。未支持无计划、明确拒绝/暂缓、未知不纳入这次生成容量统计。主表系统/窗口/ArkUI/框架5组不计为应用。

41个有明细的应用里，37个存在上述候选，4个没有可计候选；另36个只有应用名，无法计数。应用候选共465条：

| 处理 | 数量 | 含义 |
| --- | ---: | --- |
| 候选原始记录 | 465 | 不含系统/窗口/ArkUI/框架组 |
| 七类固定编辑操作可复用的记录 | 238 | 同一固定键可随明确对象绑定；不是238个不同按键 |
| 扣除后原始记录 | 227 | 尚含同动作多键位、一行双向等 |
| 语义去重并拆分方向后 | 213 | 跨应用分别计数的操作候选，不是213个全局独立能力 |
| 有候选的应用 | 37 | 不把空目录计作已覆盖 |
| 剩余候选不超过9项 | 31／37 | 含已有编辑操作足以覆盖的应用；不是用户任务覆盖率 |
| 剩余候选超过9项 | 6 | 图库、文管、备忘录、浏览器、WPS、石墨 |

**扣除的是重复UI需求，不能解释为任意应用已经接入。** 当前InputDock默认编辑绑定文本目标；对象编辑、画布历史等通过额外回调适配。文件删除、日程复制、图层撤销等要明确接到正确目标后，才能真正复用固定键。若当前上下文没有对应能力，就禁用或说明不可用，不要为了复用误操作另一个对象。

原始“删除页同意确认”（图库116行）仍保留为确认动作，没有误减成普通删除。永久删除与终止进程也保留。新建/打开/保存等同名动作可随当前文档模式复用一个槽位，但不在本轮声称合并了执行适配器。

## 九键方案的具体取舍

九格提供的是最大容量。优先让同一模式中的操作一次可见；超过9项时按任务拆组。不要让用户在一个大而杂的列表里寻找，也不要为了保持9格而摆入不相关操作。

| 场景 | 九格中的操作 | 说明 |
| --- | --- | --- |
| WPS文字格式 | 加粗、斜体、下划线；字号−、字号＋、上标；下标、居中、更多 | 正好9个点击目标；右对齐、字体设置进更多，文件操作另组 |
| WPS演示播放 | 上一步、下一步、退出播放 | 3键即可；已有演示预设继续优先 |
| MindMaster节点 | 新建、打开、同级分支、子分支、查找 | 5键；删除、撤销等复用固定区，需要正确节点绑定 |
| 红莲花浏览器 | 查找、放大、缩小、历史、打印、书签 | 6键；没有从华为浏览器借来不支持的导航 |
| 中望CAD／悟空图像 | 新建、打开、保存、另存、打印 | 5键；原表没有绘图/图层专用能力，不能称完整专业面板 |
| 酷狗播放 | 上一首、播放暂停、下一首 | 3键；源表方向须先核验 |
| 哔哩哔哩 | 前进跳转、后退跳转 | 2个规划候选；播放暂停未见单号，不额外补一个假可用键 |
| Coremail／向日葵／有道 | 无需新增 | 本表候选全可归入固定编辑操作，不代表真实应用没有其他功能 |

其中“更多”计入第9格，因此有更多时首屏最多8个直接业务操作。“播放/暂停”在表中是一个切换命令，算一个按钮；字号正负需要两个点击目标。

WPS全应用仍有46个候选：文字、表格、演示合计，并包含焦点导航、选区移动、文件操作。一行“到数据区边缘”展开为四个方向；一行“移动当前单元格”也展开为四个方向。这个总量不要求一次显示46键，更不能把它全部理解为业务专用按钮。生成器在当前对象/模式下筛选9格以内。

同样，剩余候选中的确认、取消、菜单、滚动可在合适场景复用通用输入方式，或作为当时需要的动作；本轮没有在缺少真实绑定的情况下将它们自动扣除，所以213是经过固定编辑扣除后的保守候选池，不是必须生成213个按钮。

## 尺寸与可用空间

沿用390px逻辑宽度、左右各18px、列间隔8px：内容宽354px，三列各约112.7px。三行64px高、两道8px间隔，总高度208px；若每格72px高，则总高度232px。还需要给组标题、上下内边距、上下文或编辑框留空间。触摸目标仍至少48×48。

现有共享底栏按CSS基础几何，收起约136px、展开约368px。因此9键区本身208px，加展开底栏已约576px，尚未计顶部状态、安全区、正文和Send。不能据此承诺所有手机、所有输入状态都同时完整放下九键。

建议：中部以快捷操作为主时用3×3；键盘、画板或连续调节控件占用空间时，优先保留当前操作和用户固定键，再收为一/两行或更多，不挤掉正文和Send。按住/拖动期间锁定布局。

九键＋收起固定底栏是20个入口，九键＋触控板底栏是22个入口（尚未计顶部）。视觉上保持“自适应业务动作”和“固定输入操作”两组，而不是把二十多个按钮铺成一张同权重网格。

## 产品管理判断与验证

本轮沿用已安装 analyze-feature-requests 技能的目标、价值、成本、风险方法；没有重要性或满意度调查，不编造机会分数。

1. **先复用固定七键并绑定正确对象。** 直接消除重复UI，覆盖238条候选记录。验证跨文本/文件/节点切换时复制、删除、撤销是否始终作用于正确对象。
2. **以九键验证普通应用的一屏操作集合。** 31/37个候选应用在当前清单里容得下，首轮用MindMaster、红莲花、邮件验证无需反复找菜单的收益。
3. **对六个大目录做模式拆分。** 先做WPS文字/表格/播放和文管浏览/选中文件。验证模式识别错误与布局切换成本，不用扩展到12/16键掩盖分组问题。

最小对照：同任务比较6键与9键，保持可执行能力相同，记录完整任务时间、寻找时间、误触/恢复和低头次数；同时检查固定区加自适应区的整屏密度。九键是当前值得验证的方案，清单容量统计不等于已经证明九键效率更好。
