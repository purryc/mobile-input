# Design Skill 与 Design MD 联合评审

日期：2026-10-23。状态：评审完成；规范合并尚未执行。

后续状态（2026-10-23）：用户已确认执行，合并结果见 [迁移记录](design-migration.md)；下文保留评审时意见与边界，不作为现行规则或未完成状态判断。

## 结论

**应收敛为一份主设计规范，以已有 Design Skill 为主干，把 Design MD 的有效增量合回去。** 两份正文不应继续分别维护相同的交互与生成规则。图标、组件、功能表保留独立的结构化数据；Figma 继续维护视觉与组件状态。

这意味着日常只编辑一份设计规则，生成面板时读取这份规则及其引用的定义表。它不要求把所有表格、代码、历史证据塞进同一个长文件。

现有 Notion「Design Skill」是设计规范的名称，并非已经安装的可执行 Skill。若后续需要 Codex / Claude 自动调用，`SKILL.md` 只写读取入口、输出格式与校验步骤，不再复制设计规则。

| 资产 | 负责什么 | 合并后的角色 |

| 原 Design Skill Notion 页面 | 交互、选择与组合、主题生成、场景例、设计验收 | 建议保留原页面 ID，作为主写入口；可改名「Design｜规则、生成与场景契约」。 |

| Figma / token 导出 | 视觉数值、组件变体、关键帧 | 保留原节点与来源；规范只说明应用规则和引用。 |

## 对 Claude 意见的复核取舍

- 采纳：一个规则主源、Skill 作主干、薄可执行入口、G 编号去冲突、纠正 288/368 的测量层级、恢复现有模板和场景覆盖。
- 限定：Claude 把“图标主题与 WPS 子应用”一起说成只在 MD 出现不够准确。Skill G15 已有三类子应用颜色，MD 新增的是来源解析与推导方法。
- 限定：四槽位与12格先作为不同层级的设计策略处理，不能仅凭文本判为硬冲突；默认模板仍需要验收。
- 不采纳：为已有映射的 GAP-03 / GAP-14 另造 GEN-09 / GEN-10，易增加维护负担。
- 不采纳：把 GoPaint 已有用户覆盖当成待再次确认的事项。根据现行 AGENTS 回填即可。
- 范围限定：折叠 PC 历史样例保留，不构成当前支持或恢复开发的承诺；旧 MD“这不取消产品方向”不应当作新增产品决策。
- 本轮交付联合评审和迁移方案，不执行规范重写。Claude 输出中关于必须再次获得许可的泛化建议不构成本项目规则。
