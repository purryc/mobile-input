# 触控板移动积压修复 · 2026-10-20

## 已定位

原 `InputDock` 对每个 pointermove 追加 Promise，并等待上一条命令回执后才发送。回执还等待对应完整业务状态在手机侧到达。输入采样快于往返速度时，无上限队列会按顺序回放旧位置，造成松手后光标继续追赶。

这能解释显著延迟放大；不能据此认定 Huawei-Guest 或鸿蒙系统本身是唯一原因。原生分布式完整状态仍以 1 KiB 内分片串行发送，大状态同步耗时属于后续可测的独立因素。

## 修改

- 新增单个在途命令的 PointerQueue，连续未发送移动替换为最新绝对位置；滚动合并并限幅。
- 按下、点击、松开作为有序边界保留；过量按钮输入或失败不回放旧队列。
- 断线、后台、切应用、会话更新或控件卸载清除待发事件；取消拖动只清除指针，不清空任务、材料或输入会话。
- 平板执行鼠标命令后，用一条紧凑 `pointer-ack` 回传位置与执行回执，不为每个采样发布、深拷贝或持久化整份业务状态。指针不增加业务版本；任务提交与文本编辑仍采用原有权威状态确认。
- 连续手势沿用手机本地指针终点，避免新一轮滑动从迟到的快照位置开始。应用或输入会话变化才重新初始化。
- 指针在业务增量中作为原子字段替换，兼容独立回执已移除或更新指针的情况；两种开发桥均支持新回执。
- 原生仅记录慢传输的分片数、排队和发送耗时，不记录文本、图片或凭据。

## 验证

- 核心 140 项通过，含 300 次移动压缩、按钮顺序、取消无副作用、旧回执失效、失败不重放及业务版本隔离。
- 浏览器新增 200 ms 延迟链路，120 个移动采样只需首个和最新位置，最终位置在 1.5 秒测试上限内到达；这是模拟慢链路，不作为真机时延数字。
- 桌面会话、微信采用、WorkBuddy 格式保存与真实浏览器拖选、共享键盘／触控板、断线同步、采集宽限测试通过。旧同步测试补充新输入会话握手回执，并依据未启用仍待机的规则检查状态。
- 证据：`artifacts/pointer-latency-core.log`、`pointer-latency-browser.log`、`pointer-latency-sync-retest.log`、`pointer-latency-slow-link.log`。
- Web 与两个签名 HAP 已构建并覆盖安装，数据保留；真机响应检查另记。
- 真机第一轮：仅合并队列仍不够。右移镜头稳定，但连续反向／上下移动的首张与约 3 秒后截图位置不同，记录为残余延迟，推动上面的轻量回执和本地起点修复。证据 `artifacts/device-2026-10-20/pointer-real-reverse-*`。
- 第二轮修复：Web、两端签名 HAP 构建通过并覆盖安装，140 项核心和 9 项浏览器回归通过。日志 `artifacts/pointer-fastpath-{core,browser,build}.log`、`artifacts/hap/pointer-fastpath-2026-10-20.log`。

- 第二轮首次右移录制期间，当前任务与触控板展开状态发生测试之外的变化，未出现可比较的指针；该镜头不计通过。
- 随后重新展开触控板，真实分布式链路完成三组操作：右滑、连续左／上／下滑、短距离右／左／上滑。每组首张与约 3 秒后截图的指针位置一致，未复现松手后继续追赶。首张抓取完成在 HDC 手势命令返回后约 0.66–0.69 秒，抓取自身有耗时，因此不将该数字当作端到端输入延迟。
- 真机证据：`artifacts/device-2026-10-20/fastpath-real-right-take2-*`、`fastpath-real-reverse-*`、`fastpath-real-small-*`；各组 `timing.json` 保存单调时钟和截图完成时间。测试只移动指针，没有提交、改写或批准任务。
- 此次 USB 用于 UI 操作与取图，两端通信选择鸿蒙分布式；尚未重复拔 USB 验收，连续移动中的帧率与精确输入延迟也未测量。
