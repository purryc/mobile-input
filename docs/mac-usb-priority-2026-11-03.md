# Mac 控制通道 USB 优先 · 2026-11-03

## 用户行为

用户选择“Mac 应用”并完成现有配对后，有已授权的 USB 数据连接时默认走 USB；无需手动把 Mac 地址改为 127.0.0.1。保存的无线地址保持不变，用于拔线后的恢复。连接状态区显示“USB 已连接”或“无线已连接”。此规则不改变平板演示的鸿蒙分布式／LAN 选择。

无线连接期间插入 USB：Mac 每 3 秒检查已授权 USB 手机并维护自身 39872 反向映射；手机空闲时最多每 5 秒探测 USB。仅同一桥接进程身份且持有原恢复凭据的连接可以接管。当前命令或鼠标拖拽尚未结束时延后切换。

USB 不可用时，先尝试已配对的无线地址；USB 运行中断开或超过 6.5 秒未响应也尝试恢复无线。未知结果不重试；输入保留，重新核对状态。首次配对、桥接进程重启后的授权仍沿用原机制；USB 优先不绕过配对，也不保存明文长期凭据。

## 边界

- 需运行 `npm run mac:bridge`，Mac 已安装 HDC、手机允许 USB 调试。
- 配对页只监听 Mac 本机 127.0.0.1:39873，39872 控制端口不提供配对码页面，USB 不转发配对页。
- 自动检查只读设备类型并建立本服务端口转发，不安装／重置设备、不改系统权限、不改其他端口。
- USB / 无线切换保持同一逻辑会话及执行回执，不改变已采用材料的归属。
- USB 已开始传输而尚未确认的写入不重放。断线时释放控制，界面保护草稿。
- 热点 IP 改变后可能仍需更新无线地址；USB 本身不依赖热点 IP。
