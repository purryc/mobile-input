# WorkBuddy 发送重置与材料任务（2026-10-16）

## 设计与交互

参考 [Figma 5:8710](https://www.figma.com/design/ApFLno64NcMoA17MiPFfZh?node-id=5-8710) 的任务请求卡片、整行操作、任务导航与固定输入栏。此次增加补充材料分支，保留原票据批准流程；不把普通文件选择当成票据写入授权。

- 发送成功后，提交的参数与画布保留在任务 input，附件身份保留在 sourceFiles 和消息中；旧输入与下一轮输入清空。拒绝、断线及未确认画布均不清空。
- 手机任务栏提供“补充汇报材料”待办，点击时创建或复用待补材料任务。重复点击不会创建多份。
- “选择文件”采用现有本地销售样例；不增加真实文件系统导入。选择后可补充文字，也可直接发送材料，按已有汇报请求执行本地演示。
- “切换应用采集”沿用平板端 1.2 秒轮换，WorkBuddy 下一项为 Bilibili。手机采集入口提供截图、录屏及相机，采用前保持明确任务选择；不发送图片弹幕。
- 采用成功后“返回材料任务”依据已采用附件的权威所属任务返回，恢复材料与草稿，不根据可能变化的本地选择器猜测。
- 复用现有本地 WorkBuddy 标识、输入 dock 与采集组件。新增操作图标使用设计标注的 lucide-react FileText / PanelsTopLeft / X / Check，1.65 stroke；未使用截图作为界面背景或引入临时 Figma URL。

## 真机发现与修正

- 已在两端运行新版本，通过手机“切换应用采集”进入平板 Bilibili，并拿到 960×596 原生应用窗口截图。
- 首次截图期间，分布式小包传输延迟超过常规探测/回执等待时间，手机进入重新同步而收起采集面板；随后截图仍然到达。原生连接状态保持已连接，不能把此现象直接等同于底层链路断开。
- 为采集指令和传输中的采集状态增加有上限的 30 秒回执/探测等待；收到权威快照即重置存活探测。真实断线仍立即保护输入并暂停写入。
- 类型检查、生产构建、双端签名构建及 4 项针对性浏览器回归通过（包括模拟慢截图不触发提前重新同步）；修复版已覆盖安装两端。真机修复后，重新截图并等待数据到达，面板保持打开；明确采用后显示“已加入任务参考”，点击“返回材料任务”成功回到原“补充汇报材料”。两张测试参考已从草稿移除，任务留在待补材料状态；未发送任务，未发送弹幕。本次仍连接 USB，不计作拔线验收。
